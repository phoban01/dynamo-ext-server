SPECIFICATION: [Solas specification](spec/solas.md)
  SECTION: [2.1. Table](#2-1-table)
    TEXT[!MUST]: All member clusters MUST use the same table.
    TEXT[!MUST]: The table MUST be in one AWS region.
    TEXT[!MUST]: The table MUST have a string partition key named `pk` and a string sort
    TEXT[!MUST]: key named `sk`.
    TEXT[!MUST]: The table MUST enable TTL on the attribute `expires`.
    TEXT[!MUST]: The table name MUST be a setting of the API server.

  SECTION: [2.2. Items](#2-2-items)
    TEXT[!MUST]: An object item MUST have `pk` equal to `obj#` followed by the resource.
    TEXT[!MUST]: An object item MUST have `sk` equal to the namespace, a `/`, and the
    TEXT[!MUST]: object name.
    TEXT[!MUST]: An object item MUST hold the resource version of its last write in the
    TEXT[!MUST]: number attribute `rv`.
    TEXT[!MUST]: An object item MUST hold the encoded object in the binary attribute
    TEXT[!MUST]: `value`.
    TEXT[!MUST]: A counter item MUST have `pk` equal to `rv` and `sk` equal to the
    TEXT[!MUST]: resource.
    TEXT[!MUST]: A counter item MUST hold the last issued resource version in the number
    TEXT[!MUST]: attribute `n`.
    TEXT[!MUST]: An event item MUST have `pk` equal to `ev#` followed by the resource.
    TEXT[!MUST]: An event item MUST have `sk` equal to its resource version as a decimal
    TEXT[!MUST]: string, padded with zeros to 20 digits.
    TEXT[!MUST]: An event item MUST hold the event type in the attribute `type`.
    TEXT[!MUST]: The event type MUST be one of `ADDED`, `MODIFIED`, or `DELETED`.
    TEXT[!MUST]: An event item MUST hold the encoded new object in `value`.
    TEXT[!MUST]: An event item for a `MODIFIED` or `DELETED` event MUST hold the encoded
    TEXT[!MUST]: previous object in `prev`.
    TEXT[!MUST]: An event item MUST hold its expiry time, in Unix seconds, in `expires`.

  SECTION: [2.3. Writes](#2-3-writes)
    TEXT[!MUST]: Every write MUST be one `TransactWriteItems` call.
    TEXT[!MUST]: The call MUST hold three actions: a counter update, an object action, and
    TEXT[!MUST]: an event put.
    TEXT[!MUST]: The counter update MUST set `n` to `n + 1` on condition that `n` still
    TEXT[!MUST]: has the value that the server read.
    TEXT[!MUST]: If the counter item does not exist, the counter update MUST create it
    TEXT[!MUST]: with `n` equal to 1, on condition that it still does not exist.
    TEXT[!MUST]: For a create, the object action MUST be a put on condition that the
    TEXT[!MUST]: object item does not exist.
    TEXT[!MUST]: For an update, the object action MUST be a put on condition that `rv`
    TEXT[!MUST]: equals the version that the server read.
    TEXT[!MUST]: For a delete, the object action MUST be a delete on condition that `rv`
    TEXT[!MUST]: equals the version that the server read.
    TEXT[!MUST]: The event put MUST be on condition that the event item does not exist.
    TEXT[!MUST]: Each call MUST set a `ClientRequestToken`.
    TEXT[!MUST]: If the transaction fails only on the counter condition, the server MUST
    TEXT[!MUST]: read the counter again and retry the same write.
    TEXT[!SHOULD]: The server SHOULD wait a short random time before each such retry.
    TEXT[!MUST]: If the transaction fails on the object condition of a create, the server
    TEXT[!MUST]: MUST return `409 AlreadyExists`.
    TEXT[!MUST]: If the transaction fails on the object condition of an update or a
    TEXT[!MUST]: delete, the server MUST return `409 Conflict`.
    TEXT[!MUST]: The server MUST reject a write whose event item would exceed the
    TEXT[!MUST]: DynamoDB item size limit.
    TEXT[!MUST]: The server MUST return `413 RequestEntityTooLarge` for such a write.

  SECTION: [2.4. Reads](#2-4-reads)
    TEXT[!MUST]: Every read of an object item MUST be a strongly consistent read.
    TEXT[!MUST]: Every read of a counter item MUST be a strongly consistent read.
    TEXT[!MUST]: Every query of an event log MUST be a strongly consistent query.
    TEXT[!MUST]: A get MUST return the object from its object item.
    TEXT[!MUST]: A list MUST read the counter before it queries the object items.
    TEXT[!MUST]: A list MUST read the counter again after the query.
    TEXT[!MUST]: If the two counter values differ, the list MUST retry.
    TEXT[!MUST]: If the two counter values are equal, the list MUST return that value as
    TEXT[!MUST]: its resource version.
    TEXT[!MUST]: A request for a list at an older, exact resource version MUST be served
    TEXT[!MUST]: by the watch cache, or it MUST fail with `410 Gone`.

  SECTION: [3.1. Issue](#3-1-issue)
    TEXT[!MUST]: Each resource MUST have its own counter item.
    TEXT[!MUST]: The first write to a resource MUST get resource version 1.
    TEXT[!MUST]: Each write MUST get a resource version exactly one more than the
    TEXT[!MUST]: previous write to the same resource.

  SECTION: [3.2. Order](#3-2-order)
    TEXT[!MUST]: The resource version of a resource MUST strictly increase in commit
    TEXT[!MUST]: order.
    TEXT[!MUST]: The server MUST NOT compare resource versions of two different resources.

  SECTION: [3.3. Objects](#3-3-objects)
    TEXT[!MUST]: The `metadata.resourceVersion` of an object MUST equal the version of the
    TEXT[!MUST]: write that last changed it.
    TEXT[!MUST]: The `rv` attribute of the object item MUST equal the same version.
    TEXT[!MUST]: The object in a `DELETED` event MUST carry the version of the delete.
    TEXT[!MUST]: The server MUST encode each resource version as a decimal string.

  SECTION: [4.1. Event log](#4-1-event-log)
    TEXT[!MUST]: Each write MUST add one event item to the event log of its resource.
    TEXT[!MUST]: The event item MUST have the same resource version as the write.
    TEXT[!MUST]: An event item MUST expire a set retention time after its write.
    TEXT[!MUST]: The retention time MUST be a setting of the API server.
    TEXT[!MUST]: The server MUST NOT depend on the time at which DynamoDB deletes an
    TEXT[!MUST]: expired item.

  SECTION: [4.2. Poll](#4-2-poll)
    TEXT[!MUST]: A watch from version `r` MUST deliver every event with a version greater
    TEXT[!MUST]: than `r`.
    TEXT[!MUST]: A watch MUST deliver events in version order.
    TEXT[!MUST]: A watch MUST NOT deliver the same event twice.
    TEXT[!MUST]: Each poll MUST read the counter first.
    TEXT[!MUST]: If `c` equals `last`, the poll MUST return no events.
    TEXT[!MUST]: If `c` is greater than `last`, the poll MUST query the event log for the
    TEXT[!MUST]: versions from `last + 1` to `c`.
    TEXT[!SHOULD]: The server SHOULD poll each resource at least once each second.
    TEXT[!SHOULD]: The server SHOULD NOT poll a resource more often than every 100
    TEXT[!SHOULD]: milliseconds.
    TEXT[!SHOULD]: The server SHOULD run one poller for each resource and share it between
    TEXT[!SHOULD]: watchers.

  SECTION: [4.3. Gaps](#4-3-gaps)
    TEXT[!MUST]: If the query result does not hold each version from `last + 1` to `c`
    TEXT[!MUST]: exactly once, the watch MUST end with `410 Gone`.

  SECTION: [4.4. Start](#4-4-start)
    TEXT[!MUST]: A watch with no resource version MUST first list the current state.
    TEXT[!MUST]: It MUST then deliver an `ADDED` event for each object in the list.
    TEXT[!MUST]: It MUST then continue from the version of the list.

  SECTION: [5.1. Resource](#5-1-resource)
    TEXT[!MUST]: `Device` MUST be a cluster-scoped resource in the group `solas.dev`,
    TEXT[!MUST]: version `v1alpha1`.
    TEXT[!MUST]: The solas API server MUST serve `Device` from the table.
    TEXT[!MUST]: `Device` MUST have a `status` subresource.

  SECTION: [5.2. Claim reference](#5-2-claim-reference)
    TEXT[!MUST]: A `claimRef` MUST hold the member name, the member UID, the claim
    TEXT[!MUST]: namespace, the claim name, and the claim UID.

  SECTION: [5.3. Status updates](#5-3-status-updates)
    TEXT[!MUST]: The server MUST NOT accept an unconditional update of `Device` status.
    TEXT[!MUST]: Each status update MUST carry the resource version that the client read.
    TEXT[!MUST]: The server MUST reject a status update that changes `claimRef` from one
    TEXT[!MUST]: holder to a different holder.
    TEXT[!MUST]: To move a device, a client MUST first clear `claimRef` and then set it
    TEXT[!MUST]: in a second update.
    TEXT[!MUST]: The server MUST reject a status update that sets a `claimRef` with an
    TEXT[!MUST]: empty field.
    TEXT[!MUST]: A spec update MUST NOT change `status`.
    TEXT[!MUST]: A status update MUST NOT change `spec`.

  SECTION: [5.4. Delete](#5-4-delete)
    TEXT[!MUST]: The server MUST reject a delete of a bound device.
    TEXT[!MUST]: The server MUST check this on the state that the delete removes, using
    TEXT[!MUST]: the delete condition on `rv` from section 2.3.

  SECTION: [6.1. Resource](#6-1-resource)
    TEXT[!MUST]: `DeviceClaim` MUST be a namespaced CRD in the group `solas.dev`, version
    TEXT[!MUST]: `v1alpha1`.
    TEXT[!MUST]: Each member cluster MUST store its claims in its own etcd.
    TEXT[!MUST]: `DeviceClaim.spec.selector` MUST be a label selector over `Device`
    TEXT[!MUST]: labels.
    TEXT[!MUST]: `DeviceClaim.status.phase` MUST be one of `Pending`, `Bound`,
    TEXT[!MUST]: `Suspended`, or `Lost`.

  SECTION: [6.2. Controller](#6-2-controller)
    TEXT[!MUST]: Each member cluster MUST run at most one active claim controller.
    TEXT[!MUST]: The controller MUST use a leader election lease in its own cluster.
    TEXT[!MUST]: The controller MUST NOT bind while its member is not live by its own
    TEXT[!MUST]: clock, as section 7.4 defines.
    TEXT[!MUST]: The controller MUST NOT bind while its member is draining.

  SECTION: [6.3. Bind](#6-3-bind)
    TEXT[!MUST]: The controller MUST NOT bind a claim that has a deletion timestamp.
    TEXT[!MUST]: Before it binds a claim, the controller MUST add the finalizer
    TEXT[!MUST]: `solas.dev/release` to the claim.
    TEXT[!MUST]: Before it picks a device, the controller MUST do a consistent list of
    TEXT[!MUST]: devices.
    TEXT[!MUST]: If a device in that list has a `claimRef` with the claim UID, the
    TEXT[!MUST]: controller MUST adopt that device and MUST NOT bind another.
    TEXT[!MUST]: The controller MUST pick a device from the free devices that match the
    TEXT[!MUST]: selector.
    TEXT[!SHOULD]: The controller SHOULD pick at random among the matching devices.
    TEXT[!MUST]: The bind MUST be a status update of the device that sets `claimRef`.
    TEXT[!MUST]: The bind MUST carry the resource version from the consistent list.
    TEXT[!MUST]: The `claimRef` MUST hold the UID of the member's current `Member`.
    TEXT[!MUST]: If the bind fails with `409 Conflict`, the controller MUST list again
    TEXT[!MUST]: and MUST NOT retry with the old version.
    TEXT[!MUST]: After a successful bind, the controller MUST set the claim phase to
    TEXT[!MUST]: `Bound`.
    TEXT[!MUST]: It MUST also set `status.deviceName` and `status.memberUID`.
    TEXT[!MUST]: If more than one device has a `claimRef` with the same claim UID, the
    TEXT[!MUST]: controller MUST keep the device with the lowest name.
    TEXT[!MUST]: It MUST release the other devices as section 6.4 describes.

  SECTION: [6.4. Release](#6-4-release)
    TEXT[!MUST]: When a claim has a deletion timestamp, the controller MUST release its
    TEXT[!MUST]: device.
    TEXT[!MUST]: To release, the controller MUST do a consistent list of devices.
    TEXT[!MUST]: For each device whose `claimRef` has the claim UID, the controller MUST
    TEXT[!MUST]: clear `claimRef` with a status update.
    TEXT[!MUST]: That update MUST carry the resource version from the list.
    TEXT[!MUST]: If the update fails with `409 Conflict`, the controller MUST list again.
    TEXT[!MUST]: The controller MUST NOT change a device whose `claimRef` does not have
    TEXT[!MUST]: the claim UID.
    TEXT[!MUST]: After the release, the controller MUST remove the finalizer.

  SECTION: [6.5. Phases](#6-5-phases)
    TEXT[!MUST]: A new claim MUST start in phase `Pending`.
    TEXT[!MUST]: When the controller's member is not live by its own clock, the
    TEXT[!MUST]: controller MUST set each `Bound` claim to `Suspended`.
    TEXT[!MUST]: When the member renews its lease, the controller MUST set each
    TEXT[!MUST]: `Suspended` claim back to `Bound` if its device still names it.
    TEXT[!MUST]: When the controller finds that its member UID changed, it MUST set each
    TEXT[!MUST]: claim with the old `status.memberUID` to `Lost`.
    TEXT[!MUST]: A `Lost` claim MUST NOT bind again.
    TEXT[!SHOULD]: Workloads SHOULD use a device only while its claim is `Bound`.

  SECTION: [7.1. Resource](#7-1-resource)
    TEXT[!MUST]: `Member` MUST be a cluster-scoped resource in the group `solas.dev`,
    TEXT[!MUST]: version `v1alpha1`.
    TEXT[!MUST]: The solas API server MUST serve `Member` from the table.
    TEXT[!MUST]: The name of a `Member` MUST be the cluster ID of its member cluster.
    TEXT[!MUST]: `Member.spec.leaseDurationSeconds` MUST hold the lease duration `D`.
    TEXT[!MUST]: `Member.status.phase` MUST be `Active` or `Draining`.

  SECTION: [7.2. Join](#7-2-join)
    TEXT[!MUST]: A member cluster MUST create its `Member` before it binds any device.
    TEXT[!MUST]: The member MUST use the UID of its current `Member` in each `claimRef`
    TEXT[!MUST]: that it writes.
    TEXT[!MUST]: When the controller starts, it MUST try to renew its existing `Member`.
    TEXT[!MUST]: If the renew succeeds, the controller MUST keep the UID of that `Member`.
    TEXT[!MUST]: If the `Member` does not exist, the controller MUST create a new one.

  SECTION: [7.3. Renew](#7-3-renew)
    TEXT[!MUST]: A renew MUST be an update of `Member.status.renewTime`.
    TEXT[!MUST]: The renew MUST carry the resource version that the member last read or
    TEXT[!MUST]: wrote.
    TEXT[!MUST]: After a `404 NotFound`, the member MUST join again as section 7.2
    TEXT[!MUST]: describes.
    TEXT[!SHOULD]: A member SHOULD renew every `D / 3`.

  SECTION: [7.4. Lease on the holder](#7-4-lease-on-the-holder)
    TEXT[!MUST]: The member MUST treat itself as not live from local time `S + D - M`.
    TEXT[!MUST]: The member MUST treat itself as live again only after a later renew
    TEXT[!MUST]: succeeds.

  SECTION: [7.5. Clock drift](#7-5-clock-drift)
    TEXT[!MUST]: The margin `M` MUST be at least `2 * rho * D`.

  SECTION: [7.6. Leave](#7-6-leave)
    TEXT[!MUST]: To leave, the member MUST first set its phase to `Draining`.
    TEXT[!MUST]: A draining member MUST NOT bind.
    TEXT[!MUST]: The member MUST then release each device that it holds, as section 6.4
    TEXT[!MUST]: describes.
    TEXT[!MUST]: The member MUST then delete its `Member`.

  SECTION: [8.1. Expiry on the observer](#8-1-expiry-on-the-observer)
    TEXT[!MUST]: Each member cluster MUST run a sweeper.
    TEXT[!MUST]: An observer MUST measure the lease of another member with its own clock.
    TEXT[!MUST]: The observer MUST record the local time at which it first saw the
    TEXT[!MUST]: current resource version of each `Member`.
    TEXT[!MUST]: The observer MUST treat the `Member` as expired from local time `T + D`.
    TEXT[!MUST]: The observer MUST NOT compare `renewTime` with its own clock.

  SECTION: [8.2. Delete an expired member](#8-2-delete-an-expired-member)
    TEXT[!MUST]: The sweeper MUST delete an expired `Member` with the resource version
    TEXT[!MUST]: that it observed.
    TEXT[!MUST]: The sweeper MUST NOT delete its own `Member`.

  SECTION: [8.3. Clear stale claim references](#8-3-clear-stale-claim-references)
    TEXT[!MUST]: The sweeper MUST do a consistent list of devices first.
    TEXT[!MUST]: The sweeper MUST then do a consistent list of members.
    TEXT[!MUST]: For each device whose `claimRef` names a member UID that is not in the
    TEXT[!MUST]: member list, the sweeper MUST clear `claimRef`.
    TEXT[!MUST]: The clear MUST be a status update with the resource version from the
    TEXT[!MUST]: device list.
    TEXT[!MUST]: If the clear fails with `409 Conflict`, the sweeper MUST skip the device
    TEXT[!MUST]: until its next run.
    TEXT[!MUST]: The sweeper MUST run at least once every `D`.
