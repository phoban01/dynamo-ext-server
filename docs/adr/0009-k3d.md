# ADR 0009: Run the clusters with k3d

Status: accepted

## Context

The demo runs three member clusters that come up on their own, run
solas, and join through the shared table. The end-to-end tests and the
smoke test need clusters too. The development VM has 16 GB of memory,
and running out of it ends the session.

A kind cluster uses 1.5 to 2 GB. A k3d cluster with only what solas
needs uses about 360 MB. We measured this with k3d 5.9.0.

## Decision

All clusters run with k3d: the demo, the end-to-end tests, and the
smoke test. Clusters use the image `rancher/k3s:v1.37.0-k3s1`, which
matches the Kubernetes libraries of solas. Traefik, the service load
balancer, and metrics-server are off. `scripts/k3d-lib.sh` holds the
shared cluster functions.

## Consequences

- Three clusters use about 1.1 GB, so they fit next to other work.
- Each cluster is a Docker container, so the shared dynamodb-local can
  join the same Docker network as the clusters.
- `sigs.k8s.io/e2e-framework` supports k3d, so the tests can use it.
- Cluster names still start with `e2e-`, and scripts delete only those.
- k3s differs from upstream Kubernetes in a few places. The demo does
  not depend on those.

## Rejected alternatives

- kind. It works, but three clusters use 5 to 6 GB.
- k3s on the host with no containers. Clusters would share ports and
  files, and cleanup is harder.
